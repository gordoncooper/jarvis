# CONTRACT: app-hosting

Hosted apps are untrusted: one folder each in the apps repository, deployed into `app-<name>` and held there by admission. A feature, off until `app-hosting` is listed under `features` in `values/switches.yaml`; with it off, the env renders none of the objects below. The env lists each app it runs in `values/apps.yaml` (`schema/apps.schema.json`): its pinned version, its grants and whether its backups are on. How to write and turn on an app: [docs/add-a-hosted-app.md](../../../docs/add-a-hosted-app.md).

## Offers

| What | Detail |
| --- | --- |
| The app file | `<name>/app.yaml`, an `App` (`hosting.jarvis.io/v1alpha1`). Its fields, defaults and meaning are the CRD's, `crd/app-crd.yaml`: `network.web` (entries: `name`, `service`, `port`, `hostnames`, `ownRoute`), `network.ports` (`listen`, `target`, `protocol`), `network.egress` (`internet`, `lan`, `apps`), `network.callers`, `volumes` (`name`, `backup`), `resources`, `risky`, `chart` (`url`, `version`, `values`). Every network field defaults closed. `python -m jarvis.apps.check <folder>…` (`--repo <dir>`) also refuses unknown keys; the app-check Action (`.github/actions/app-check@<tag>`) runs it in the apps repository's CI. |
| Web names | Each web entry: `<name>.apps.<dns_suffix>` for the one with no name, `<name>-<entry>.apps.<dns_suffix>` for a named one, on 443 through the apps door: listener `apps` of Gateway `platform-gateway/jarvis`, with Certificate `wildcard-apps` (`*.apps.<dns_suffix>`, internal CA); an entry's granted custom hostnames use listener `apps-granted`. Both admit routes only from labelled app namespaces ([traefik](../../platform/traefik/CONTRACT.md)). An app ships no route; one marked `ownRoute` ships its entry's HTTPRoute, naming `${app_host}` or a granted custom hostname. |
| Per listed app, applied as the platform account by `app-<name>-wiring` | Namespace `app-<name>` (label `hosting.jarvis.io/app: <name>`; annotations: `apps-domain` (`apps.<dns_suffix>`), pod/service/LAN ranges, one `hosting.jarvis.io/<grant>` per grant, `volsync.backube/privileged-movers: "true"`; Pod Security `warn`/`audit` `restricted`); tenant `flux-system/app-<name>` with Role `app`; NetworkPolicies `default-deny` (`prune: disabled`), `same-namespace`, `cluster-dns`; LimitRange `app` (default 100m/128Mi limits, 50m/128Mi requests); Kustomization `app-<name>-file`, reading only `<name>/app.yaml` at the pinned tag; RoleBinding `app-grant-revoke`. An app with no `chart` also gets Kustomization `app-<name>`, reading only `<name>/deploy/` there, after the app file. |
| Per listed app with a `chart`, rendered into `flux/generated/apps.yaml` from its app file at the pinned tag | In `flux-system`: chart source OCIRepository `app-<name>` (the app file's `oci://` chart; `prune: disabled`), ConfigMap `app-<name>-values` (the app file's values), and HelmRelease `app-<name>`: as the tenant, release `<name>` installed into and stored in `app-<name>`, `valuesFrom` that ConfigMap with the env entry's `values` inline on top, no wait, a failed install or upgrade retried each minute. Both carry `substitute: disabled`, so values reach Helm as written. The HelmRelease keeps prune on: dropping the app uninstalls it. An image-only app names a generic chart such as bjw-s app-template. |
| Derived from the App (GeneratingPolicies `app-derive`, `app-derive-backups`) | ResourceQuota `app` (`resources`, `services.nodeports: 0`, LoadBalancers up to `network.ports`). Per web entry but an `ownRoute` one: HTTPRoute `app-web[-<entry>]` on listener `apps` to its `service` and `port`, and `app-hostnames[-<entry>]` on `apps-granted` for its custom hostnames the env grants. Only when asked: `app-web` (Traefik to the app's pods, once it has a web entry), `app-ports` (granted `lan-port` targets), `app-internet` (any port to public addresses; never RFC 1918, `100.64.0.0/10`, link-local or the env's ranges), `app-lan-all` (asked `lan: [all]` and granted `lan-all`), `app-lan` (asked and granted `lan-target`, on its ports), `app-apps` / `app-callers` (one side each), `app-backups` (to `restic-apps:8000` while the app's backup credential exists). An allow the App stops asking for goes on its next update. |
| Backups (`backups/`) | `backups` in the app's entry (default on). With them on and a `backup: true` volume in its file, the app needs its own credential, `secrets/app-<name>/backups-restic-app-<name>.sops.yaml`: `jarvis secrets --env <env>` mints it, validate requires it once the env is bootstrapped, and the render registers it. Secret `platform-backups/backups-restic-app-<name>`: the app's own password and login `ns-app-<name>`, repository `rest:http://restic-apps.platform-backups.svc.cluster.local:8000/ns-app-<name>/pvc-<pvc>`. GeneratingPolicy `pvc-backup-app` gives each bound `app-*` PVC Secret `restic-<pvc>` from that credential only and ReplicationSource `<pvc>` as core's `pvc-backup` does ([backups](../../platform/backups/CONTRACT.md)); with no credential, neither. |
| Apps rest-server | Service `platform-backups/restic-apps`, port 8000: core's image and hostPath, `--private-repos`, so user `ns-app-<name>` works only under `ns-app-<name>/`. Its htpasswd is built at start from each registered credential's `htpasswd` key; the user name comes from the folder, not the sealed line. Never mounts `backups-restic`. |
| Admission (`policies/admission.yaml`, ValidatingAdmissionPolicies, `failurePolicy: Fail`) | `app-identity`: `app-<name>` exactly when labelled `<name>`; an App only in its own namespace. `app-tenant`: the tenant writes only in `app-<name>`, only ConfigMaps, Secrets, Services, PVCs, Deployments, StatefulSets, Jobs, CronJobs, HTTPRoutes, PDBs, HPAs and its App. `app-file` and `app-grants` (one binding each on every labelled namespace): Pod Security `restricted`; volumes only configMap, secret, emptyDir, PVC, projected, downwardAPI, csi, ephemeral; PriorityClass `hosted-app`; memory request equal to limit; PVCs only declared volumes (`backup: none` exactly when `backup: false`), no `volumeName`/`dataSource`/`dataSourceRef`; an HTTPRoute names its hostnames, each a web entry's (one label under `apps.<dns_suffix>`) or a granted custom one; the tenant's own HTTPRoute serves only an `ownRoute` entry; Services ClusterIP, or LoadBalancer only on granted `network.ports` with `allocateLoadBalancerNodePorts: false`, named `<name>.apps.<dns_suffix>`; no other `coredns.io/hostname` or external-dns hostname on any app Service; no NodePort, ExternalName or `externalIPs`. A risky item, custom hostname or LAN port passes only when the App asks **and** the env grants it. A labelled namespace with no App refuses everything. |
| VolSync carve-out | Jobs and claims the VolSync controller creates, and Pods the job controller creates for them, pass. The scheduler's and binder's UPDATE of a VolSync-owned PVC passes; CREATE does not. Removing only `kubernetes.io/pvc-protection` from a terminating VolSync-owned PVC passes. |
| Lowest priority | PriorityClass `hosted-app` (`-1000`, `preemptionPolicy: Never`), set on every workload by MutatingPolicy `app-priority` (`failurePolicy: Ignore`); `app-file` refuses any other class, so an unmutated workload is refused, not promoted. |
| A granted LAN port's name | MutatingPolicy `app-lan-name` (`failurePolicy: Ignore`) sets `coredns.io/hostname: <name>.apps.<dns_suffix>` on each app LoadBalancer, which App DNS answers with the Service's address; `app-grants` refuses an unnamed or otherwise named one. |
| Revoke stops what runs | CronJob `platform-app-hosting/app-grant-revoke` (namespace layer `feature`, Pod Security `restricted`), every five minutes: in each listed app's namespace, dry-run re-admits every Pod, unfinished Job, Service and HTTPRoute, and deletes those refused by a rule marked `grant: ` (pods get 30 seconds). Deletes a derived `app-lan-all`, `app-lan` or `app-ports` holding more than granted. A gone App stops all of its objects. PVCs, data, backups and VolSync movers stay. Its account reads Apps, lists namespaces, and patches or deletes pods, Jobs, Services, HTTPRoutes and NetworkPolicies in app namespaces; no Secret, PVC or core namespace. |
| Grants (the app's `grants` in `values/apps.yaml`) | `privileged`, `root`, `host-network`, `host-path`, `hostname <name>` (outside `dns_suffix`), `lan-port <port>/<TCP\|UDP>` (not a port core or the node holds, `RESERVED_PORTS` in `jarvis/apps/values.py`; one app's only), `lan-all`, `lan-target <name> <cidr> <port>/<TCP\|UDP>` (inside `lan_cidrs`; name a DNS label other than `all`). No blanket grant. LAN addresses live only in the env's repository. |

## Expects

| What | From |
| --- | --- |
| The apps repository at `apps_git_repo_url`, https, no credential; each app at its tag `<name>/v<x.y.z>` (its `version`), never a branch | the env |
| The app's objects meet admission; `${app_host}` is their only variable; image and probes are the app's; no two listed apps make one web name | the app, checked at its pinned tag by `jarvis validate` |
| A chart's host, reachable with no credential; its output, with the app's and the env's values, meets admission as `deploy/` does (no ServiceAccount, CRD or Ingress) | the app, checked by `helm template` in `jarvis validate` and the app-check Action |
| The app's entry in `values/apps.yaml` and the render `flux/generated/apps.yaml` committed | [schema](../../../schema/CONTRACT.md), `jarvis render` |
| `lan_cidrs` once a line grants `lan-all` or `lan-target` | `values/cluster-vars.yaml` |
| A `backup: true` volume's credential, sealed by the env | [docs/backups.md](../../../docs/backups.md#app-credentials) |
| Kyverno, cert-manager (`platform-controllers`); Traefik in `kube-system` | core |

## Health

| Check | Pass |
| --- | --- |
| `app-<name>-wiring`, `app-<name>-file`, `app-<name>` (its Kustomization, or its chart's HelmRelease) | Ready (`jarvis up` and `jarvis verify` wait on them; an app with no valid app file fails) |
| `jarvis verify` component `apps` | bindings `app-file` and `app-grants` exist; each app namespace has its label, `default-deny`, `cluster-dns`, `same-namespace`, LimitRange `app`, and annotations equal to the env's grants; each web entry but an `ownRoute` one has its `app-web[-<entry>]` route; HTTPRoute hostnames are a web entry's or granted; a declared `backup: false` volume is reported, any other `backup: none` fails; a dropped `app-` namespace is reported |
| `jarvis verify` component `apps`, backups | with the app's backups on, each bound app volume not `backup: none` has a ReplicationSource (core's `backups` checks its freshness); with them off, nothing is checked. `restic-apps` logs `app users: <n>` |
| `app-grant-revoke` | last Job succeeded (not in `jarvis verify` yet); a probe with no policy answer fails the run |
| `app-hosting` (`jarvis validate`) | the env wires exactly the apps it lists, each with its baseline objects and grants |

## Limits

- A granted custom hostname gets Traefik's default certificate.
- Traefik reaches an app's pods on any port once it has a web entry: a route names a Service's port, not a pod's. Only core's routes and the ones admission holds pick where Traefik sends.
- An `ownRoute` entry's route reads only `${app_host}`, so a named `ownRoute` entry is reached on a granted custom hostname only. A chart's values read no variable; the env's `values` name the app's host where it needs it.
- source-controller pulls the `oci://` chart an app file names from `flux-system`, outside the app's egress policy: a new chart address arrives with the app's pin, and nothing but its reader checks where it points.
- Kyverno derives the quota and allows after admission; until then the app has the baseline's deny and the LimitRange defaults only.
- Memory is contained, not guaranteed: a core pod over its requests can still be evicted first, and the kernel's OOM killer goes by QoS, not priority.
- A revoke takes effect within the wiring's interval plus five minutes, stops the whole object, and leaves finished Jobs.
- Kyverno re-derives allows and routes when the App changes, not when the env's grants or ranges change; the reconciler closes an allow, or stops a route, that holds too much.
- Egress is by address and port, never hostname. No LAN discovery, no internet-facing app, LAN ranges IPv4 inside RFC 1918.
- `lan-all`, or a `lan-target` range holding a node, reaches node-side endpoints (the API, kubelet, Traefik) as any LAN device can.
- Movers in app namespaces run privileged. The namespaces and CRD keep `prune: disabled`; turning hosting off leaves them for the operator.
